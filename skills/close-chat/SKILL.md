# close-chat — закрытие сессии по чек-листу

Четыре шага в конце работы: нет подвешенных вопросов → changelog + готовые
OpenSpec changes → убрать мусор → закоммитить только touched в этом чате.

**Принцип:** быстро, минимум вопросов. Коммитим только touched. Чужое в
`git status` не трогаем. Вопрос — только при реальном блокере или неоднозначной
принадлежности файла к сессии. Удаления — только whitelist.

Caveman на подтверждениях ослабляется: вопросы и предупреждения — нормальным
русским.

## Когда вызывать

- `/close-chat`, `/close_chat`, «закрыть чат», «закрытие сессии», «конец чата»,
  «заверши сессию»
- Пользователь просит привести репозиторий в порядок перед уходом

Не вызывать автоматически в фоне.

## Аргументы

- Без аргументов — полный пайплайн.
- `--dry-run` — план по шагам, без изменений и коммита.
- `--skip 0|1|2|3` — пропустить шаг (можно повторять).

## Подготовка

Перед шагом 0 собрать:

1. **touched-список** — файлы, созданные/изменённые агентом в сессии (tool
   calls Write/Edit, логически связанные untracked). Уверенно touched — без
   вопроса. «Неоднозначно» — только если нет признаков принадлежности к сессии.
2. **OpenSpec touched** — `openspec/changes/<id>/`, которые трогали в чате.

## Шаг 0. Открытые вопросы

Блокеры, не допрос. Нет блокеров — «открытых вопросов нет», шаг 1.

Источники (молча):

- TodoWrite — `in_progress` / `pending`.
- **OpenSpec touched** — `tasks.md` с прогрессом <100%.
- **`implementation-notes.md`** в touched changes —
  [docs/ai/openspec-implementation-notes.md](../../docs/ai/openspec-implementation-notes.md):
  явные отклонения, нерешённые TODO («отложено», «спайк», «не решено»).
- **Открытые заявки на ревью** — `handoffs/<slug>/rN-request.md` со статусом
  «затык» / «не закончено» без парного `rN-result.md`
  ([review-request](../review-request/SKILL.md) / [review](../review/SKILL.md)).
- История чата — явно подвешенные вопросы без ответа.
- `CHANGELOG.md` — незакрытые TODO в `[Unreleased]`, если агент их оставлял.

Действие:

- Ничего — шаг 1.
- Иначе — **один** список, **один** вопрос: «доделать сейчас / оставить заметку
  в `research/` / закрыть как есть».
- Зафиксированное отклонение в `implementation-notes.md` без требования решения —
  строкой, не вопросом.

Не переходить к шагу 1 при нерешённых блокерах из ответа пользователя.

> `implementation-notes.md` удаляется **до** archive на шаге 1
> ([openspec-archive-change](../openspec-archive-change/SKILL.md)). На шаге 0 не
> удалять.

## Шаг 1. Changelog и архивация OpenSpec

### 1a. Changelog

Если сессия меняла user-facing поведение (CLI, MCP, API, установка):

- Запись в `CHANGELOG.md` под `## [Unreleased]` есть → «changelog ок».
- Нет, но изменения user-facing → предложить пункт
  ([release](../release/SKILL.md): `### Added` / `### Changes` / `### Fixes`).
  `--dry-run` — только черновик.
- Только внутренний рефакторинг / тесты → «changelog не нужен».

Не коммитить changelog отдельно — stage на шаге 3.

### 1b. OpenSpec archive

Кандидаты — **только OpenSpec touched** с tasks 100% после шага 0.

Для каждого:

1. Sync delta-specs в `openspec/specs/` (правило по умолчанию в
   [openspec-archive-change](../openspec-archive-change/SKILL.md)).
2. Архивировать через тот же скилл.
3. Сообщить: что заархивировано, куда переехало.

Changes <100% — не трогать: «не архивирован: `<id>`, прогресс N%».

## Шаг 2. Очистка мусора

`git status` **только по touched-списку**:

| Категория | Действие |
| --- | --- |
| **Whitelist** untracked: `tmp/`, `*.tmp`, `*.bak`, `*.orig`, `scratch_*`, `_tmp_*` | Удалить, перечислить |
| **Touched-черновики**: отладочные скрипты, одноразовые логи, «на разок» | Удалить, перечислить |
| **Полезное агентам** (заметки, исследования) | Не удалять — одним вопросом: оставить / `research/` / удалить |
| **Вне touched** | Не трогать — «вне скоупа: N файлов» |

Перед удалением — список «удалить:», **одно** подтверждение. `--dry-run` — только
список.

Спорные (не whitelist, не явный черновик) — не удаляем.

## Шаг 3. Коммит изменений сессии

- **touched** → в коммит без вопросов (если не «стоп» на шаге 0).
- **чужое** → исключить; сводка «вне коммита: N файлов».
- **неоднозначно** → один общий вопрос: включить / вне / удалить.

### Порядок

1. Краткий итог: «к коммиту: N», «вне: M».
2. **Один коммит по умолчанию.** Дробить только при явно несвязанных темах
   (например, два разных OpenSpec change) — один вопрос «один или N?».
3. Stage: `git add <path>` по каждому touched. **Не** `git add -A` / `git add .`.
4. Сообщение — Conventional Commits, subject ≤50 chars (см.
   [caveman-commit](../../.agents/skills/caveman-commit/SKILL.md) при наличии).
   `git commit` с HEREDOC — **только после явного «да» / «коммить»**.
5. Не пушить.

`--dry-run` — классификация и черновик сообщения, без коммита.

**После коммита (одной строкой):** если менялся `src/` — напомнить `pnpm test`;
не запускать автоматически.

## Что скилл НЕ делает

- Не пушит.
- Не запускает `qmd collection add`, `qmd embed`, `qmd update`.
- Не трогает `~/.cache/qmd/index.sqlite`.
- Не правит `research/` без запроса (только предложить на шаге 0/2).
- Не архивирует OpenSpec changes, которые не трогали в сессии.
- Не запускает тесты и сборку автоматически.
- Не каскадит при «стоп».
- **Не задаёт лишних вопросов** — см. принцип выше.

## Границы

- Коммит — только по явному подтверждению.
- Удаление — whitelist автоматически; остальное — подтверждение.
- Нет правок в сессии — шаги 1–3 пропустить: «коммитить нечего».
